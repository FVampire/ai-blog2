# AI Chat 配置与验证

## 配置

在「后台 → 集成 → AI」保存模型服务商、地址、模型和密钥，再执行连接测试。测试使用已经保存的配置，并产生少量模型调用。原生 Anthropic 使用 Messages 协议，其余服务商使用 OpenAI 兼容协议；选择「其他」时必须填写完整 API 基础地址。

全局 AI 与公开助手两个开关都必须开启。公开配置接口只返回显示信息和能力状态；管理员读取 AI 密钥时也只获得空占位，未修改的密钥不会被覆盖。输入新值替换密钥，主动清空修改后的输入框可清除密钥。

当前文章模式仅加载已发布正文，超过 24000 字符会明确提示截断。全站模式需要单独配置 Embedding 密钥、基础地址和模型，维度固定为现有数据库索引的 1024。更换模型后通过向量管理重建索引；不同模型的旧索引不会参与查询。检索失败会显示错误，无匹配会显示提示与空来源列表。

新配置项在管理员保存时通过设置接口创建。配额功能需要先通过部署迁移流程应用 `db/migration-add-ai-usage-limits.sql`，创建共享计数表和过期索引；未迁移或数据库故障时聊天会返回 503，不会绕过额度限制。本次代码修改不执行线上迁移、不修改现有设置、不重建线上向量。

## 访客配额与全站预算

后台 AI 配置新增三项：

| 配置                            | 默认值    | 统计范围                                         |
| ------------------------------- | --------- | ------------------------------------------------ |
| `ai_global_requests_per_minute` | 4         | 所有公开聊天的模型调用，滚动 60 秒，范围 1–10000 |
| `ai_anonymous_requests_per_day` | 5         | 每个可信来源 IP 发起的聊天次数，范围 1–100000    |
| `ai_daily_request_budget`       | 0（关闭） | 全站每天的模型调用次数，范围 0–10000000          |

每日在北京时间零点重置；午夜不会清空仍在滚动分钟窗口内的记录。每次模型调用前原子检查并计数，MCP 引起的后续模型调用也受限；模型失败、取消不退还已扣次数。访客配额在读取知识库和连接工具前扣除，后续失败仍计数，工具循环不会重复扣访客配额。全站预算按请求次数统计，不等于金额或 Token 预算，不包含 Embedding、后台测试、索引任务及 MCP 服务自身可能产生的外部调用费用。

计数使用 PostgreSQL 事务与共享锁，支持多进程和多实例，重启不清空。过期访客计数在后续请求时清理，表内只保存按日哈希的来源标识和计数，不保存原始 IP、消息或密钥。相同出口 IP 共享访客配额，换 IP 仍可能绕过单访客限额，全站上限继续生效。到达上限后返回明确提示；流开始前返回 HTTP 429 和 `Retry-After`，流中遇到限制返回 SSE error 并停止追加调用。

## 输入模型审查

后台 AI 设置中的「输入内容审查」默认开启，可配置模型名称和 3–60 秒超时（默认 15 秒），并测试已保存的配置。默认推荐 `qwen3.5-flash`，审查使用现有模型服务商、API 地址和密钥，不会自动切换到外部服务商。公司接口必须提供此模型或填写其支持的模型名称；原生 Anthropic 接口应填写兼容的 Claude 模型名。模型不可用时暂停回答，不会静默跳过审查。

默认模型参考 [Qwen3.5-Flash 官方说明](https://www.alibabacloud.com/help/en/model-studio/qwen3-5-flash)。Qwen3 系列审查请求显式关闭思考模式（[官方参数说明](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)），最多输出 256 Token，不调用工具、不自动重试；其他模型需由所用网关提供适合快速分类的配置。

流程为：格式校验 → 访客配额 → 审查调用配额 → 模型审查 → 文章/Embedding 检索与 MCP 连接 → 回答调用配额 → 回答。审查读取完整客户端历史（含不可信 assistant 消息），根据最新问题及上下文判断犯罪实施、色情、赌博、毒品和危险服务器操作；策略明确允许科普、预防、性健康教育和正常安全运维。只接受明确且一致的 JSON 分类，拦截提示由服务端按类别生成，不展示模型自由文本、内部错误或用户原文。超时、异常、无效分类都停止后续检索和回答。

每次审查计入全站频率和每日请求预算，即普通问答通常需要 2 次模型调用；匿名配额仍只扣 1 次。被拦截或检查失败也不退还已扣次数。管理员显式关闭审查后恢复直接回答流程。后台连接测试不占公开访客配额，但仍产生模型调用费用。

这是输入模型审查，不是输出审核或历史签名验证。模型分类仍可能误判或被绕过，现有 MCP 白名单和只读权限边界必须保留。自动化测试验证模拟审查结果下的放行、阻断、异常和调用顺序，不代表公司真实模型的分类准确率；上线时应使用实际模型验证代表性的违规请求与正常问题。

## MCP

服务器的「已启用」不等于允许匿名访问。先在 MCP 管理配置并启用服务器，再在 AI 设置检测服务器 ID，获取工具名称及只读状态。

公开工具白名单格式：`{"服务器数字ID": ["工具名称"]}`，例如 `{"1": ["search_articles"]}`。只有管理员明确列出且工具元数据声明 `readOnlyHint: true`、未声明破坏性的工具能进入访客 Agent。默认白名单为空；写入工具不会向匿名访客开放。白名单是安全边界，请只添加经管理员审查的工具。

关闭访客选择后，服务端也会强制只允许默认的公开服务器。公开列表不会返回命令、参数、URL、环境变量或 headers；工具卡片仅展示名称和执行状态，不返回原始参数或结果。

## 协议与资源限制

`POST /api/ai/chat` 仅支持 SSE。请求携带 requestId、messageId、messages、mode（none/article/site）、可选 articleId、mcpServerId（未启用为 null）。事件为 start、status、text-delta、sources、warning、tool-start、tool-result、done、error。

请求上限 200KB、单条消息 12000 字符、最多 40 条、历史总计 48000 字符。客户端只发送已完成的模型对话，欢迎语与界面提示不进入上下文。单次请求限时 90 秒，Agent recursionLimit 为 12，输出最多 64000 字符并受模型 Token 上限限制。MCP 配置超时会应用于工具调用，实际公开调用最多 60 秒。

请求频率及每日额度使用上述数据库共享计数；另保留单进程每来源并发 2、总并发 8 的资源保护。仅在反向代理会覆盖用户提交的 X-Forwarded-For 且应用无法被绕过代理直接访问时设置 `TRUST_PROXY=true`；否则所有访客共用保守配额，避免伪造请求头绕过限流。代理应关闭 SSE 缓冲并允许超过 90 秒的响应时间；接口会返回 `X-Accel-Buffering: no`。

服务端日志只记录请求 ID、阶段、耗时、输出字符数、工具调用数和结果，不记录密钥、对话正文及工具参数。关闭窗口会保留正在生成的回答；停止按钮会取消请求，组件卸载也会取消。会话仅存于当前标签页 sessionStorage，24 小时内可恢复，新建对话会清除旧记录。

## 验证

- `pnpm test`：自动运行 `lib/**/*.test.ts`，其中包含 AI 测试：SSE 任意字节分块、UTF-8、断流、配置白名单、参数限制、取消、代码复制、真实本地 HTTP 模型/MCP 模拟调用。
- `pnpm build`：生产构建，构建期会执行类型检查和 ESLint，任一报错都会中断构建。

上线前用已保存的真实服务配置执行模型、Embedding、MCP 连接测试，并检查公开接口无密钥。若旧版配置接口曾部署并返回过密钥，应轮换相关凭据。
