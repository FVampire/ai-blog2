# 墨灵项目演示页实施计划

## 一、项目目标

在个人作品集的项目展示中新增独立案例页 `/projects/moling`，将小说创作项目“墨灵 Moling”包装为一款已经完整落地、设计成熟、功能闭环的商业级桌面产品。

本页面是纯项目演示页面，以最终完整形态作为现有功能进行展示。页面不披露原型状态、开发阶段或功能完成度，也不区分“当前实机”与“未来概念”。整体目标是让访问者在短时间内感知墨灵的产品定位、核心能力、设计品质与技术深度。

核心品牌表达：

> 让一部长篇，始终记得自己。

产品定位：

> 集故事规划、章节创作、长篇记忆、智能审稿与世界状态管理于一体的 AI 小说创作工作台。

页面元数据：

- `title`：`墨灵 Moling · 长篇 AI 创作工作台 - 五月的火`
- `description`：`为长篇小说而生的桌面创作系统。墨灵持续维护角色、设定、伏笔与章节状态，让每一次生成都建立在完整故事上下文之上。`
- Open Graph 图使用 Hero 合成图。

## 二、展示原则

1. 最终概念直接作为成熟产品功能展示，不出现“概念界面”“未来版本”“开发中”“当前进度”“原型”等说明。
2. 页面以产品体验和视觉冲击为中心，不写成技术文档、开发日志或复盘报告。
3. 不直接使用早期验证截图；所有核心画面统一为最终产品的视觉语言。允许用图像生成工具制作“伪造”的最终产品界面，也允许录制后再调色、裁切、配音轨静音的短视频来展示动态过程。
4. 不展示未经处理的真实本地小说数据。界面中的书名、章节、角色和正文统一使用附录中的演示长篇《南岸无灯》。
5. 文案只描述产品能力和用户价值，不罗列代码目录、测试数量或内部实现细节。
6. 技术架构只作为产品可信度的补充，以简洁、视觉化的方式呈现。
7. 案例页没有下载、安装、购买或“即将上线”入口。访问者应感到这是完整产品，但不会误以为此刻可以安装。
8. 页面上的可动效果按媒介分工：页面动效用 CSS；需要看见软件内部在运转的，用视频；需要看见界面细节的，用生成 PNG。不要在静态 PNG 上用 CSS 假装连线或光标在动。

## 三、品牌与视觉方向

### 3.1 视觉关键词

- 东方书斋
- 温润纸张
- 深墨文字
- 鎏金细节
- 晨光与静谧感
- 桌面级专业工具
- 克制、精密、可信赖

### 3.2 色彩与材质

- 主背景：米白、暖灰和宣纸色。
- 主文字：深墨棕与近黑色。
- 强调色：低饱和鎏金色。
- 状态色：松柏绿、朱砂橙等克制的辅助色。
- 材质：纸张纹理、柔和阴影、细边框和轻微玻璃层次。
- 案例页用 CSS 变量收口，例如 `--moling-paper`、`--moling-ink`、`--moling-gilt`、`--moling-pine`、`--moling-cinnabar`。不要复用《遗忘潮汐》的青墨 token。

### 3.3 排版与构图

- 使用大字号品牌标题与大面积留白建立高级感。
- 产品界面采用宽屏桌面窗口构图，突出导航、编辑器、AI 面板和状态系统的层次。
- 内容区使用杂志式网格和不对称排版，避免普通后台项目介绍页的观感。
- 移动端将复杂工作台拆分为可阅读的纵向模块，不直接缩小桌面界面。

### 3.4 字体

全站标题字体 Instrument Serif 撑不住中文大标题，墨灵案例页必须单独处理：

- 中文品牌标题、章节大标题：思源宋体 / Noto Serif SC，或等效中文衬线，只在 `/projects/moling` 加载。
- 英文品牌名 Moling、小标签、编号：可继续用 Instrument Serif。
- 正文与界面说明：沿用站点现有无衬线。
- 生成图内部的中文必须是真实汉字，禁止假文字、乱码或英文 lorem 冒充正文。

### 3.5 动效

页面层（CSS，写在案例页里）：

- Hero 产品窗口缓慢进入并建立空间层次。
- 滚动时窗口铬依次强调导航、正文、上下文区域（用遮罩或光晕，不移动 PNG 内部像素）。
- 所有页面动画支持 `prefers-reduced-motion`：减动时取消进入位移、视差和自动播放。

资产层（视频，不在 PNG 上模拟）：

- 创作流水线：短视频循环，步骤依次点亮。
- 可选：章节生成时右侧 AI 面板的流式输出；关系图谱的缓慢呼吸。
- `prefers-reduced-motion` 或移动端弱网：停在对应海报帧，不自动播放。

## 四、画面实现契约

三种媒介各做各的，禁止混用职责。

| 媒介 | 用来做什么 | 不用来做什么 |
| --- | --- | --- |
| HTML / CSS | 页面排版、书斋背景、桌面窗口铬（标题栏、三点、阴影）、吸顶标签、文案、架构标签 | 不要用 HTML 重绘整套 IDE |
| 生成 PNG | 工作台、规划、角色、Canon 等“看清楚界面”的画面 | 不要靠 CSS 让图里的光标、连线、进度条动起来 |
| 录制后剪辑的视频 | 流水线、生成过程、图谱呼吸等“看见软件在工作”的画面 | 不要把未调色的早期原型录像直接上页 |

默认组合：`ProductWindow` 提供 HTML 窗口铬，铬内放 PNG 或 `<video>`。访客看到的是“桌面上的成品应用”，铬是真的，内容是生成或剪辑的。

### 4.1 PNG 伪造

允许用图像生成工具制作最终产品截图，不要求从 `writing_assistant` 实机导出。

约束：

- 所有图共用同一套窗口布局：左导航 / 中编辑或画布 / 右 AI 或检查器，色彩和字号与 3.2、3.4 一致。
- 所有图只出现附录中的书名、角色、章节，禁止每张图各编一套故事。
- 生成后必须人工检查中文。错字、假字、重复笔画一律重做或后期把附录文案烧进去。
- 关键可读信息（品牌口号、章节名、能力卡片标题）优先写在 HTML 里，不要完全依赖图内小字。
- 图内可以有短正文，但只摘附录片段，不要生成大段不可控小说。

构图分工，避免做六套完整 IDE：

- `hero`：唯一一张“四区同屏”的合成全景，供首屏和归档卡封面。
- `chapter-studio` / `outline-workbench` / `story-world` / `canon-memory`：同一布局下的分镜特写，突出该节要讲的区域，不要重新发明导航结构。
- 移动端不单独生成一整套界面，从桌面图裁切主内容区即可。

建议导出：

- Hero 与归档封面：宽边约 2400px，16:10 或 3:2。
- 分节展示图：宽边约 1800px。
- 格式 PNG 或高质量 WebP。本仓库 `next.config.js` 已设 `images.unoptimized: true`，体积靠导出时控制，不要假设 Next Image 会自动出多尺寸。

### 4.2 线下实跑取材，演示态秒出

分两段，不要混在同一次操作里。

**取材（线下，可打真实模型）：**  
生成、审稿、局部修订、多模型竞态这类“文字质量决定画面是否像样”的能力，先在 `writing_assistant` 或任意 playground 里用真实模型多跑几轮。只使用附录里的人物、伏笔和章节目标作为约束。从结果里挑表现最好的写回附录，再拿去出图、剪视频。

适合实跑再挑的：

- 多模型竞态的三路正文（并排出现，最后选中一路）
- 审稿意见和一致性提示的措辞
- 局部修订后的那一句
- 规划拆解、影响范围等短摘要

不适合实跑进成片的：转圈等待、超时、空响应、安全拒绝、调试 JSON、API 错误。这些一律丢掉，不要为了“过程真实”留在演示里。

**回放（成片和页面，禁止再打模型）：**  
八步按时间轴播放已经挑好的稿，看起来像系统在几秒内走完闭环，包括竞态。竞态在演示里是“三路结果几乎同时就位，再点选一路”，不是真的等三路推理结束。

秒出指的是**压缩过的演示时间**，不是 0 帧闪过：

- 每步停留约 1–2 秒，让人看清当前输入和输出。
- 正文用极快打字或整段推入，不要真的等流式接口。
- 可以有很短的“进行中”状态（鎏金高亮、引用卡片亮起），但不要出现转圈超过 0.5 秒，也不要出现真实 token / 延迟 / 报错。
- 成片总长仍控制在 8–15 秒，循环点落在定稿后的 Canon 更新，再切回第一步。

必做一条：

- `agent-pipeline`：按节拍回放附录「流水线预设稿」。生成步要能看见多模型竞态：三路候选几乎同时出现，随后选中附录指定的那一路写入编辑器。

可选，有余力再做：

- `chapter-generate`：竞态三路并排展开，选中稿写入正文，右侧引用卡片按预设顺序亮起。
- `canon-graph`：预设的「双重署名」从推进中跳到待确认，节点呼吸。同样不跑图谱算法。

制作方式（任选，结果要像同一套成品 UI）：

1. **推荐：** 取材完成后，用附录终稿做可重放脚本（fixture / mock，不再打模型），按节拍播放后录像。再裁窗口、调成书斋色。
2. 对生成 PNG 做有限动态（高亮、进度、文字叠入）再导出。观感必须接近 Hero / 分镜 PNG，不能看起来像另一个产品。

不要做的：

- 对着镜头开真实生成、真实竞态等待、真实审稿接口。
- 把落选的差稿、失败请求、重试和调试日志剪进成片。
- 后期把真实慢速录像加速到看不清字。秒出靠预设回放，不靠 8 倍速。

成片规格：

- 静音。页面用 `muted`、`loop`、`playsInline`、`autoPlay`。
- 必须有海报帧，减动和移动端用海报，不自动播。
- 每条同时提供 `webm` 与 `mp4`。单条目标小于 4MB。桌面自动播放；768px 以下默认海报，点击再播。

### 4.3 页面动效与无障碍

- 鼠标视差只作用于窗口铬和光影，位移极小。减动时关闭。
- 分节展示用吸顶标签切换 PNG / 视频，交互对齐现有 `VisionShowcase`：`role="tablist"`，键盘可切。
- 每张图有具体 alt，写《南岸无灯》里正在发生的事，不写“产品截图”。
- 视频加无障碍短描述；减动时只渲染海报。

## 五、信息架构

九个模块都保留。真正费资产的是 Hero 全景、章节工作台 PNG、流水线视频；规划 / 世界 / Canon 用同一套标签切换容器，不要做成三个独立巨型区块。

### 5.1 全屏 Hero

目标：第一屏即建立“成熟桌面产品”的印象。

内容：

- 品牌名：墨灵 Moling。
- 核心口号：让一部长篇，始终记得自己。
- 一句话定位：为长篇小说而生的 AI 创作工作台。
- HTML 窗口铬内放入 `hero` 合成 PNG：项目导航、章节编辑器、故事上下文和 AI 协作面板同屏。
- 产品标签：长篇记忆、故事规划、智能审稿、本地创作。

交互：

- 产品窗口随页面进入轻微上浮。
- 鼠标移动产生非常轻微的光影与景深变化。
- 向下滚动时主界面自然衔接到产品能力介绍。

### 5.2 产品价值主张

目标：用简洁文案解释墨灵解决的问题。

建议表达：

- 长篇小说真正困难的不是写出一段文字，而是让数十万字始终属于同一个世界。
- 墨灵持续维护角色、关系、设定、伏笔、事件和章节状态，让 AI 创作建立在完整故事上下文之上。

核心能力卡片（HTML，不上图）：

- 全书级上下文
- 情节持续规划
- 角色与世界状态
- 审稿与局部修订

### 5.3 智能章节工作台

目标：展示产品最核心、最有说服力的工作场景。

画面：`chapter-studio` PNG；可选叠 `chapter-generate` 视频。

界面内容应能在图中读到：

- 左侧：卷章结构、章节状态、搜索与写作进度。
- 中央：沉浸式正文编辑器、章节提要和场景结构。
- 右侧：AI 协作、引用上下文、生成状态与修改建议。
- 底部或浮层：保存状态、字数、版本和任务进度。

展示能力（由旁白文案承担，不靠图内小字讲完）：

- 根据章节目标和故事状态生成正文。
- 生成过程中持续引用角色、伏笔和前文事实。
- 对章节进行审稿、局部重写，以及多模型竞态后的版本选择。
- 定稿后自动同步章节摘要与故事状态。

### 5.4 故事规划中枢

目标：体现墨灵不是单次文本生成器，而是长篇项目管理系统。

画面：`outline-workbench` PNG，放进与 5.5、5.6 共用的标签切换。

图中应能看到：故事总纲、分卷、故事弧、章节 Slot、受影响章节提示。旁白说明：上层规划改动后可局部调整，不破坏未受影响内容。

### 5.5 活的故事世界

目标：用强视觉模块展示人物与世界的持续变化。

画面：`story-world` PNG；有余力再加 `canon-graph` 视频。

图中应能看到：沈晚白 / 顾衡 / 阿苔的档案或立绘、关系连线、南岸与档案库。旁白说明称谓、别名和状态如何随章节更新。

### 5.6 长篇记忆引擎

目标：建立墨灵最独特的产品差异。

画面：`canon-memory` PNG。

建议主文案：

> 每一次定稿，都在更新这个世界对自己的记忆。

图中应能看到：Canon 事实、伏笔“埋设 / 推进 / 回收”、一条一致性提示。旁白说明后续生成会选用真正相关的上下文。

### 5.7 多智能体创作流水线

目标：用动态流程展示完整生成闭环。这是视频主场，不要用静态流程图凑数。

流程（成片和侧边说明都用产品语言，不出现内部接口名）：

1. 理解章节目标。
2. 选择相关故事上下文。
3. 构建章节与场景计划。
4. 多模型竞态，生成正文候选并选出一路。
5. 审稿与一致性检查。
6. 根据意见进行局部修订。
7. 用户确认并定稿。
8. 同步摘要、角色状态、Canon 与影响通知。

节拍（与附录预设稿一一对应，总长约 13 秒）：

| 秒 | 步骤 | 画面上应立刻出现 |
| --- | --- | --- |
| 0–1.5 | 理解章节目标 | 第七章目标整句，不是“正在思考” |
| 1.5–3 | 选择上下文 | 五张引用标签同时或依次亮起 |
| 3–4.5 | 构建场景计划 | 四个 Slot 名称 |
| 4.5–6.5 | 多模型竞态 | 三路候选几乎同时出现，标签用产品名而非接口名 |
| 6.5–7.5 | 选中写入 | 附录指定的那一路进入编辑器，另外两路收成缩略 |
| 7.5–9 | 审稿与一致性 | 那条顾衡到访冲突提示 |
| 9–10.5 | 局部修订 | 正文里冲突句被改成附录定稿句 |
| 10.5–11.5 | 用户定稿 | 状态变为已定稿 |
| 11.5–13 | 同步记忆 | 双重署名变为推进中，影响通知出现 |

表现形式：

- 铬内循环播放按上述节拍剪好的 `agent-pipeline` 视频。
- HTML 侧边列出八步，当前步鎏金，与片子节奏大致对齐即可，不要求逐帧精确。
- 减动或移动端：八步列表 + 海报帧。

### 5.8 本地创作底座

目标：补充工程可信度与数据安全感。本块不上产品截图。

展示重点：

- 桌面应用体验。
- 本地项目与本地数据库。
- 写作内容由用户掌控。
- 多模型配置、任务分工，以及生成时的多路竞态选择。
- 自动保存、版本历史、恢复与完整导出。

架构图仅使用产品层级表达：

```text
创作界面 → 桌面运行时 → 智能创作引擎 → 本地故事数据库
```

技术栈以小型标签呈现：Tauri、Next.js、Rust、Python、SQLite。不把 “Agent Workflow” 写成技术栈名称。

### 5.9 结尾品牌区

目标：以情绪化表达结束案例页。

建议文案：

> 从第一句话，到最后一个伏笔回响。

> 墨灵陪伴的不是一次生成，而是一整个故事成为它自己的过程。

视觉：复用 Hero 图或加一层书斋光影，品牌名，返回 `/projects`。没有 CTA 按钮。

### 线下取材规则

1. 用附录章节目标和上下文，让至少两个模型各跑若干次正文 / 审稿 / 修订。
2. 只留下仍然遵守故事边界、中文干净、语气像同一本书的结果。
3. 为竞态选三路：一路作为写入编辑器的优胜稿，另外两路明显略弱但仍然可读，用来衬托选择，不要放明显崩坏的稿。
4. 把终稿覆盖进本附录后，再生成 PNG 和视频。页面不读模型，只读附录。
