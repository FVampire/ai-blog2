# 遗忘潮汐案例页 · 世界观与角色扩展实施计划

## 一、项目目标

为已上线的案例页 `/projects/forgetting-tide` 补上「世界设定」「角色档案」「对立面」「同行生物」四个章节，并把章节顺序从「先讲规则」改为「先建立世界」。

当前页面的问题不是内容不足，而是入口顺序错了：读者在第二屏就被推进「一局里发生什么」的系统说明，此前没有任何理由在意这个世界。本次改动的目标是让访问者在前三屏先认识维拉汀、认识潮汐、认识几个人，之后再进入规则层。

同时页面已有一批做好却没接线的资产和样式（详见第七章、第六章），本计划优先把它们接上，再列出需要新制作的美术清单。

页面元数据保持不变，仅补 Open Graph 图（见 6.2）。

## 二、展示原则

1. **第一章说真话，后续章节留悬念。** 灰烬医院（序章 + 首章）设定已完备，允许并且应当展示真实的最终美术与实机界面。第二章及以后的内容不编造资产、不伪造截图，改为「封存条目」呈现：给出已确认的世界事实和制作状态，不给画面。
2. 与《墨灵》案例页不同，本页**不隐藏制作状态**。潮汐的世界规则本身就是"记录会被抹去"，把制作进度作为可见信息反而与题材同构，也避免让评审误判可玩范围。
3. 新增章节以「让人想了解这个世界」为第一目标，不是补充设计文档。世界设定要给悬念和画面，不要给数据表。
4. 缺少角色立绘时，不使用灰底占位图或"图片待补"字样。改用第五章的档案卡契约，让缺位成为叙事的一部分。
5. 关键可读文字（人名、地名、世界规则、章节状态）一律写在 HTML 里，不烧进图片。生成图内不要出现中文小字。
6. 新增章节沿用现有暗潮色板与表格化描边语言，不引入第二套视觉体系。
7. 五个属性阵营（微光 / 锈铁 / 回声 / 幽影 / 生息）在世界设定里落地为五个地理区域，让系统层的克制环在世界层有出处，而不是凭空的一组标签。

## 四、新增章节内容规格

### 4.1 01 / WORLD 世界设定

**版式**：满幅横向地图带（不用 `.worldSection` 的左右分栏，原因见 7.2）+ 下方两栏文案。

**结构**：

1. `sectionHeading`：`01` / `WORLD` / 标题「潮汐不带走东西，<br />它带走东西之间的关系。」
2. 满幅地图带：`concepts/world-atlas.png`，`object-fit: cover`，高度 `clamp(320px, 34vw, 520px)`，左右各一道向内的深色渐变收边。图上用绝对定位的 HTML 标记点标注三处：`潮灯之家`、`灰烬医院`、`潮汐之眼`。标记为 1px 青色描边小圆点 + 9px→11px 标签，不烧进图片。
3. 下方左栏：世界导言（两段，14px）。
4. 下方右栏：`.memoryLayers` 四层记忆列表（复用现有样式，70px 标签栏 + 说明）。
5. 收尾：`.worldRule` 珊瑚色左边框单句。

**文案（本次现编，与现有页面已有的暗示保持一致）**：

导言第一段：

> 维拉汀不缺记录。它缺的是记录之间还连着的那根线。每隔一段时间，遗忘潮汐从断名海涌上来，漫过城邦、病院与档案馆。潮水退去后，纸还在，字还在，只是没有人能说清这一页属于谁、又为什么被写下。

导言第二段：

> 于是维拉汀人学会了一件事：与其抢救记录，不如抢救关系。潮灯之家是最后一座还在运转的灯塔，它不靠燃料，靠"仍被记得"发光。你，一名姓名已被整齐切除的寻潮者，带着三只由残响长成的生物，走回那些还没被完全冲散的地方。

四层记忆（`.memoryLayers`）：

| 标签 | 说明 |
| --- | --- |
| 表层 | 姓名、日期、编号。潮汐第一批带走，且不留痕迹。 |
| 中层 | 事件、因果、谁对谁做了什么。需要有人复述，才留得下。 |
| 底层 | 手势、气味、走惯的那条路。潮汐碰不到，身体先记得。 |
| 残响 | 被带走的部分不会消失。它们脱离主人，长成会动的形状。 |

世界规则（`.worldRule`）：

> 潮汐不销毁事物，只销毁事物之间的联系。所以在维拉汀，遗忘不是空白，是错位。

**五区与五属性的对应**（放在导言下方一行 `.creatureTags` 风格的标签条，或并入 `memoryLayers` 之后的一个小网格）：

| 区域 | 属性 | 一句话 |
| --- | --- | --- |
| 微光林线 | 微光 | 会自己发光的林带，夜里比白天亮。 |
| 锈铁荒原 | 锈铁 | 旧护甲与机械残骸堆成的坡，风一吹整片在响。 |
| 回声群岛 | 回声 | 说出去的话会隔几天从另一座岛回来。 |
| 幽影裂谷 | 幽影 | 光进不去，只有被观察过的东西才有形状。 |
| 生息湿垣 | 生息 | 拆掉多久都会重新长回来的墙。 |

灰烬医院位于幽影裂谷与断名海之间的滩地——这解释了为什么首章的核心机制是"观察让事物获得形状"。

### 4.3 03 / ANTAGONIST 对立面

**版式**：复用 `.prototypeFeature`（`1.55fr .45fr`，min-height 560px）。图片列 AR 约 1.86，`paper-matron.png` 是 1.777，改用 `contain` 后基本无裁切。

**版式**：复用 `.creatureSection`（`.7fr 1.3fr`）——左文案，右 `.evolution` 三阶段网格。

**结构**：

1. 左栏：`sectionHeading` 简版 + 标题「它们不是抽到的，<br />是被认出来的。」+ 两段文案 + `.creatureTags` 标签（微光属性 / 植忆 / 实体召回 / 主线生物 / 三阶段成长）。
2. 右栏：`.evolution` 三格，放 `creatures/lamp-rabbit-1/2/3.png`（三张均为 1024×1024 带透明通道，当前完全未被使用）。每格底部标签：`STAGE 01 · 灯尾兔影` / `STAGE 02 · 引路灯尾` / `STAGE 03 · 万家灯火`。
3. 下方补一条实机佐证：`screenshots/creature-detail.png`（灯笼菇图鉴界面，含进化路线，当前未被使用），`aspect-ratio: 16/9`、`contain`，角标 `IN-GAME CODEX · 灯笼菇`。

**文案**：

> 残响不是怪物，是某个人被潮汐带走的那一部分，脱离主人之后长出的形状。你不能抓它，也不能召唤它。你只能先观察清楚它到底是谁的残响，把仍然指向它的碎片收齐，再让灯塔把那个核心稳定下来。

> 所以三阶段成长不是稀有度提升。轮廓一直是同一个，变的是它和你之间累积了多少同行记忆，以及在最后它选择怎么解释自己。

## 五、档案卡：立绘缺位的处理契约

角色立绘尚未制作。为避免读成"页面没做完"，采用**叙事化缺位**，而不是占位图。

### 5.1 视觉规则

每张档案卡顶部有一个 `aspect-ratio: 3/4` 的立绘位。在美术到位之前，该位渲染为：

- 底：`#0a1d22`，叠一层 2px 间距的斜向扫描线（`repeating-linear-gradient`，透明度 0.04）。
- 中央：该角色姓氏的巨大衬线字（`寻` / `伊` / `塞` / `米`），`font: italic 400 clamp(96px, 12vw, 168px) var(--font-display)`，颜色 `#12303a`（极低对比，作为纹理而非文字）。
- 面部位置：一道珊瑚色（`--tide-coral`）横向切除条，高 14px、宽 62%，居中偏上，透明度 0.72。
- 左下角标：`ARCHIVE P-01`；右下角标：`影像已剥离`，均为 9px→11px。
- 边框：1px `#29464b`，与页面其他卡片一致。

### 5.2 为什么这样成立

本作的世界设定就是"姓名与影像被潮汐整齐切除"。一个被涂改的档案照片位，是设定内的产物，而不是工程缺口。页面上不出现任何"待补""TODO""Coming soon"字样。

### 5.3 美术到位后的替换成本

立绘位是独立组件 `CastPortrait`，只接 `src?: string`。传入 `src` 就渲染 `next/image`（`contain`，透明 PNG），不传就渲染上述档案态。替换四张图不需要改版式，也不需要改 CSS。

## 八、同批修复的 P0 缺陷

本次要改 `page.tsx` 与整份 CSS，以下缺陷在同一遍里修掉，否则新增内容会放大它们。缺陷来源是本轮设计审核的实测结果。

### 8.1 目录导航 sticky 失效

`.page` 上的 `overflow: hidden` 使 `.caseNav` 的 `position: sticky` 失去视口参照，滚到 4000px 时导航条 `top` 实测为 −3160px，即完全滚走。

改法：删除 `.page` 的 `overflow: hidden`。若删除后出现横向溢出，改用 `overflow-x: clip`（不创建滚动容器，不破坏 sticky）。

验证：滚到页面任意位置，导航条固定在顶部；点击任一目录项后目标章节标题不被导航条遮挡（`scroll-margin-top` 现为 64px，导航实高 50px，符合）。

### 8.2 界面截图被裁切

所有 UI 类图片当前 `object-fit: cover`，实测裁切量：`camp.png` 18.0%、`camp-art-pass.png` 17.9%、`testimony-wall-final.png` 12.2%、`camp-final.png` 9.8%。见证墙左侧标题与营地终版右侧的「选择远征地点」按钮均被切掉。

改法：`.visionImage`、`.loopImage`、`.processRail article > div`、新增的图鉴与关键视觉容器一律改 `contain`，容器改 `aspect-ratio: 16/9` 与素材对齐，去掉固定 `min-height`。氛围类整图（`hero`、地图带）保留 `cover`。

### 8.3 移动端首屏重叠

390px 下 `.heroCopy` 底边 762px、`.heroMeta` 顶边 749px，重叠 13px；悬浮助手按钮（770–820px）覆盖同一区域。

改法：700px 断点内 `.heroCopy` 的 `bottom` 从 190px 提到 240px，`.lead` 收到 3 行（`-webkit-line-clamp`）或缩短文案；`.heroMeta` 加 `background: rgba(4,15,19,.72)` 保证被覆盖时仍可读。

### 8.4 音频与文案不一致

文案称"可无缝循环"，`<audio>` 无 `loop`，32 秒后停止。改法：加 `loop`；`autoPlay={playing}` 改为 `useEffect` 内显式 `play()` / `pause()`；进度条高度 3px→5px、底色提到 `#2f5158`。

### 8.5 新增章节的标题栅格

`.sectionHeading` 为 `140px 1fr .55fr`，1920px 下中栏仅约 720px，而 `h2` 被 clamp 到 76px，一行只放得下 9.5 个中文字，已导致 5 处末行孤字（如「战斗、技能与生物生 / 态」）。

改法：`.sectionHeading` 改为 `140px 1fr` 两栏，说明段落移到标题下方并限宽 560px；`h2` 加 `text-wrap: balance` 兜底。**新增章节的标题必须在这条修复之后再定稿**，否则会新增孤字。

字号收敛（全页 56.6% 字符处于 ≤10px）与中文标题去斜体范围更大，不在本计划内，另立一轮。
